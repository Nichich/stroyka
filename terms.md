# Техническое задание

## 1. Общие сведения

- Название: сайт компании Добрострой 25.
- Заказчик: строительная компания Добрострой 25, Владивосток.
- Назначение: сайт-витрина с каталогом, корзиной и заявками плюс админка для управления контентом.
- Сроки и порядок работ обсуждаются отдельно, в этом ТЗ фиксируем требования к самому продукту.

## 2. Назначение и цели

Назначение - дать клиенту возможность посмотреть товары с ценами, отфильтровать под свои задачи и оставить заявку. Менеджеру - удобно управлять каталогом и SEO без программиста.

Цели:
- собирать заявки на плитку, бордюры и блоки;
- приводить трафик из поиска по местным запросам;
- закрывать вопросы по качеству, документам и доставке прямо на сайте.

## 3. Характеристика объекта

Объект - публичный сайт компании плюс закрытая админка. Контент: товары (с типом, ценой, цветом, формой, высотой, назначением, наличием), категории, отзывы, сертификаты, статичные блоки (о компании, доставка, контакты). Аудитория и трафик подробно описаны в task.md.

## 4. Требования к системе

### 4.1 Требования к функциям

Публичная часть:
- Главная: первый экран (hero), блок преимуществ, слайдеры с товарами, блок "что делает наш продукт лучшим выбором", блок каталога со скачиванием.
- Каталог: список товаров, фильтры (тип, цена через слайдер, цвет, форма, высота, назначение), сортировка по популярности и цене, мобильный фильтр в виде модалки, пагинация/навигация.
- Карточка товара: фото, цена за единицу (м или м²), наличие, характеристики.
- Корзина: добавление товара, изменение количества, оформление заявки.
- Страница доставки.
- Страница сертификатов (соответствие ГОСТ 17608-2017, ТП 244, ТП 204).
- Страница отзывов с разбивкой по типу клиента (компании, дилеры, частники) и рейтингом.
- Страница о компании.
- Контакты: телефон, почта, адрес, встроенная Яндекс.Карта.
- Обратная связь / заявка.

Админка (закрытая, через авторизацию):
- вход по логину и паролю, токен в куках;
- товары: создание, редактирование, удаление;
- управление цветами, опциями, категориями;
- заказы/заявки;
- SEO-настройки страниц;
- профиль.

### 4.2 Требования к данным

- Товар: id, slug, название, картинка, цена (значение, валюта, единица), наличие, параметры сортировки (тип, цена, цвет, форма, высота, назначение), популярность.
- Цвета заданы парами название - hex (бежевый, серый, красный, чёрный, коричневый, синий).
- Категории: тротуарная плитка, стеновые блоки, бордюры.
- Отзыв: автор, город, рейтинг, текст, тип клиента.
- Сертификат: название и файл.

### 4.3 Требования к интерфейсу

- Дизайн по макету из Figma, фирменный акцентный цвет - оранжевый.
- Адаптив: десктоп и мобильные (есть отдельные мобильные ассеты и мобильный фильтр).
- Понятная навигация: шапка с меню и корзиной, подвал с контактами.
- Прелоадер при загрузке.
- Страница 404.

### 4.4 Требования к надёжности и безопасности

- Админка доступна только после авторизации, неавторизованного перекидывает на вход (middleware).
- Служебные страницы (админка, авторизация) закрыты от индексации.
- Токен хранится в куках, протухание обрабатывается через перехватчики запросов.

### 4.5 Требования к SEO

- Уникальные title и description на страницах, ключевые слова под местные запросы.
- robots.txt и sitemap.
- Open Graph для нормального вида ссылок при репосте.
- Редактирование SEO-полей из админки.

### 4.6 Технические требования

- Next.js 15 (App Router), React 19, TypeScript.
- Tailwind CSS для стилей.
- TanStack Query для запросов, Axios как клиент.
- React Hook Form + Zod для форм и валидации.
- Сборка через Node 20+ или Bun, деплой через Docker (в репозитории есть Dockerfile).

## 5. Состав и содержание работ

1. Вёрстка по макету и сборка страниц.
2. Каталог с фильтрами и сортировкой.
3. Корзина и заявки.
4. Подключение API и админки.
5. SEO-обвязка.
6. Тестирование, оптимизация (см. optimize.md), деплой.

## 6. Порядок контроля и приёмки

- Проверяем по списку функций из раздела 4.1.
- Смотрим на десктопе и телефоне.
- Проверяем, что заявка из корзины и с контактов реально уходит.
- Проверяем, что админ может добавить/изменить/удалить товар и поправить SEO.
- Прогоняем базовую проверку скорости (см. optimize.md).

## 7. Источники

- Макет в Figma.
- Контент и параметры товаров от заказчика.
