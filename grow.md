# Гитфлоу проекта

Как ведём ветки и коммиты. Флоу простой, без перегруза.

## Ветки

- main - стабильная версия сайта. В неё ничего не пушим напрямую, только через PR. То, что в main, должно работать.
- task - материалы по учебному заданию (эта ветка). С main не смешивается.
- feature-ветки - под каждую задачу своя ветка от main.

Фича-ветки называем по смыслу задачи, например:
- catalog - каталог
- feature/catalog-page - страница каталога
- busket - корзина
- cards - карточки товара
- certificates - сертификаты
- preloader - прелоадер
- reviews - отзывы

Допустимы оба варианта именования - короткое (catalog) и с префиксом (feature/catalog-page), главное чтобы по названию было понятно, что за задача.

## Как работаем по шагам

1. Обновляем main:

```bash
git checkout main
git pull origin main
```

2. Заводим ветку под задачу:

```bash
git switch -c catalog
```

3. Делаем задачу, коммитим по ходу:

```bash
git add .
git commit -m "каталог: фильтр по цвету"
git push -u origin catalog
```

4. Когда фича готова - открываем Pull Request в main, ревью, мержим. Подробнее в prstrategy.md.

5. После мержа подтягиваем main к себе и берём следующую задачу:

```bash
git checkout main
git pull origin main
```

## Коммиты

- Пишем по-русски, по делу, в настоящем времени или коротким описанием: "каталог: добавил сортировку по цене", "фикс: корзина не считала количество".
- Один коммит - одно осмысленное изменение, не сваливаем всё в один.
- Не коммитим node_modules, .env, .next и прочую сборку - они в .gitignore.
